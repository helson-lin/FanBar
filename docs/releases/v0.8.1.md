### 修复 / Fixes

- **SMC 拒绝写入时的后台重试更可靠** — 0.7.3 加入的后台重试，在你手动切换模式、Mac 睡眠或唤醒时，可能和还没完成的重试写入同时发给控制服务。现在新的操作会等这次写入结束，唤醒也不会在上一次写入还没返回时再发一次。跨过唤醒才成功的写入现在也能正确恢复原来的模式 (#140, #114)
  **More reliable background retries when the SMC refuses fan writes** — the background retry added in 0.7.3 could send a request to the control service while one of its writes was still in flight, when you switched modes or the Mac slept or woke. A new action now waits for that write to finish, and a wake no longer sends a second write before the first one answers. A write that only succeeds across a wake now turns your mode back on correctly (#140, #114)

- **放弃重试时说明真正的原因** — 以前只要重试结束就提示"SMC 仍然拒绝写入"，即使写入其实从未发出，或控制服务一直没有回应。现在只有 SMC 确实拒绝写入时，才会在重试结束时建议重启 Mac；控制服务没有回应或没能重试时，会如实说明，风扇仍由 macOS 调节。第一次通知也不再立刻建议重启 (#140, #114)
  **Says why it gave up retrying** — FanBar used to report "the SMC still refuses fan writes" whenever the retries ended, even if no write had gone out or the control service never answered. A restart is now suggested only when the SMC really refused the writes, and only once the retries end. If the control service never answered or FanBar couldn't retry, it says so, and macOS keeps controlling the fans. The first notification no longer suggests a restart straight away (#140, #114)

- **偶发读取错误不再让风扇控制一直失效** — 控制服务启动时检测风扇模式所用的 SMC 键，如果这一次读取偶然失败，以前会一直认为这台 Mac 不支持手动控制，或在切换模式时报出"F0md failed (-1)"，直到控制服务重启。现在只有确认键不存在时才这样判断，读取失败会在下次重新检测；即使检测失败，交还 macOS 时也会清掉所有可能的模式键。与 SMC 的连接意外断开时，控制服务会重新连接并重试一次 (#140)
  **A one-off read error no longer breaks fan control until a restart** — when the control service starts, it checks which SMC keys set the fan mode. If that read happened to fail, it used to decide this Mac doesn't support manual control, or switching modes failed with "F0md failed (-1)", until the service restarted. That now happens only when the key really doesn't exist; a failed read is retried the next time. Handing the fans back to macOS still clears every possible mode key even when the check failed. If the connection to the SMC drops, the control service reconnects and tries once more (#140)
